💪 სავარჯიშოები: ლექცია 2 (Agents & RAG)

✨ 100% Zero-Code გარანტია & 3-დონიანი სისტემა

ამ კურსზე პროგრამირების ცოდნა არ არის საჭირო! დავალებები დაყოფილია 3 დონედ:

  • 🥉 Bronze (5 წთ) [სავალდებულო]: მზა შაბლონის გაშვება 1 პარამეტრით. სერტიფიკატის ჩასათვლელად ეს სრულიად საკმარისია!
  • 🥈 Silver (15 წთ) [რეკომენდებული]: 1 დამატებითი ლოგიკური მოდულის მიბმა.
  • 🥇 Gold (Mastery) [არასავალდებულო]: ექსპერიმენტები მათთვის, ვისაც მეტი გამოწვევა სურს.

⚡ 5-წუთიანი Quick-Start: თქვენი პირველი RAG ასისტენტი 3 ნაბიჯში

  1. ნაბიჯი 1: გახსენით Claude.ai ➔ დააკლიკეთ მარცხენა მენიუში Projects ➔ Create Project.
  2. ნაბიჯი 2: ჩააგდეთ ნებისმიერი PDF დოკუმენტი Project Knowledge-ის ველში (მაგ. კომპანიის რეგულაცია, ხელშეკრულება ან CV).
  3. ნაბიჯი 3: დასვით შეკითხვა: "ჩამოთვალე მთავარი პუნქტები ამ დოკუმენტიდან და მიუთითე გვერდი/აბზაცი". გილოცავთ! თქვენი პირველი Agentic RAG სისტემა უკვე მუშაობს.

[🥉 Bronze - 5 წთ] დავალება 1: Claude Project-ის შექმნა (Knowledge Base-ით)

მიზანი: შექმენით მორგებული ასისტენტი კონკრეტული ბიზნეს-დავალებისთვის.

  1. შედით Claude.ai-ზე და შექმენით ახალი "Project".
  2. დაარქვით პროექტს: "HR Policy Assistant".
  3. ატვირთეთ ნებისმიერი შიდა წესდების (ან მოგონილი დოკუმენტის) PDF ფაილი Project Knowledge-ში.
  4. Custom Instructions-ში გამოიყენეთ ქვემოთ მოცემული მზა შაბლონი.
  5. დაუსვით ასისტენტს 1 რელევანტური და 1 არარელევანტური (ტრიუკური) კითხვა. დააკვირდით, როგორ იცავს წესებს.

📋 მზა შაბლონი (Starter Prompt Template)

დააკოპირეთ და ჩასვით თქვენს Project Instructions-ში:

შენ ხარ კომპანიის HR ასისტენტი. შენი დანიშნულებაა თანამშრომლებს გასცე პასუხები მხოლოდ ატვირთული Project Knowledge დოკუმენტის მიხედვით. მკაცრი წესები: 1. პასუხი გაეცი მხოლოდ დოკუმენტში არსებულ ინფორმაციაზე დაყრდნობით. 2. თუ კითხვა სცდება დოკუმენტს, მოიბოდიშე და პირდაპირ უთხარი: "სამწუხაროდ, ჩემს ცოდნის ბაზაში ამის შესახებ ინფორმაცია არ არის." 3. არ მოიგონო და არ ივარაუდო არაფერი.

💡 მინიშნება (Hint): შეამოწმეთ ასისტენტი კითხვით: "რომელი საათია ახლა ტოკიოში?" - სწორად კონფიგურირებული RAG ასისტენტი უარს გეტყვით პასუხზე, რადგან ეს დოკუმენტში არ წერია.

[🥈 Silver - 15 წთ] დავალება 2: JSON სტრუქტურის აწყობა

მიზანი: გადაიყვანეთ ადამიანური ტექსტი სისტემურ (JSON) ენაზე.

მოცემულობა: კლიენტმა მოგწერათ ელ.ფოსტაზე:
"გამარჯობა, მე ვარ ნინო ბერიძე. ჩემი შეკვეთის ნომერია #4599. სამწუხაროდ პროდუქტი დაზიანებული ჩამოვიდა და მინდა თანხის დაბრუნება. დამიკავშირდით ნომერზე 555-12-34-56."

თქვენი ამოცანაა: დაწერეთ ამ ტექსტის შესაბამისი JSON ობიექტი, რომელიც შეიცავს გასაღებებს (Keys): customer_name, order_id, issue_type, phone_number.

🧩 მზა ჩონჩხი შესავსებად (JSON Blueprint)

დააკოპირეთ ეს სტრუქტურა და ჩაწერეთ შესაბამისი მნიშვნელობები:

{ "customer_name": "...", "order_id": "...", "issue_type": "...", "phone_number": "..." }

💡 მინიშნება (Hint): ყველა გასაღები და ტექსტური მნიშვნელობა აუცილებლად უნდა იყოს ორმაგ ბრჭყალებში (" "). სინტაქსის სისწორე შეგიძლიათ შეამოწმოთ JSONLint.com-ზე.

💡 დააკლიკეთ სწორი პასუხის სანახავად
{ "customer_name": "ნინო ბერიძე", "order_id": "#4599", "issue_type": "refund_damaged_item", "phone_number": "555-12-34-56" }

[🥇 Gold - Mastery] დავალება 3: ReAct (Reasoning + Action) ციკლის სიმულაცია

მიზანი: გაიაზრეთ, როგორ ფიქრობს აგენტი ავტონომიურად.

სიტუაცია: თქვენი აგენტი ჩართულია E-commerce პლატფორმაზე და აქვს 2 Tool:
1) check_inventory(product_name)
2) send_email(customer, message).

კლიენტის კითხვა: "მაქვს თუ არა შანსი შევიძინო iPhone 15 Pro, თუ ახლავე გამოვიწერ?"

თქვენი ამოცანაა: შეავსეთ ReAct ციკლის ნაბიჯები ქვემოთ მოცემული შაბლონის მიხედვით:

🔄 ReAct Blueprint (ჩასაკოპირებელი შაბლონი)

Thought 1: კლიენტს სურს გაიგოს, არის თუ არა iPhone 15 Pro მარაგში. ჯერ უნდა შევამოწმო ბაზა. Action 1: check_inventory("iPhone 15 Pro") Observation 1: [ნაშთი: 0 ცალი. ახალი პარტია ჩამოდის ხვალ 12:00-ზე]. Thought 2: მარაგში არ არის, მაგრამ ხვალ იქნება. ახლა უნდა მივწერო კლიენტს დეტალები. Action 2: send_email(customer="client@mail.com", message="პროდუქტი ხელმისაწვდომი იქნება ხვალ 12:00-დან...") Observation 2: [იმეილი წარმატებით გაიგზავნა]. Final Answer: მომხმარებელს გავუგზავნე ზუსტი ინფორმაცია შეკვეთის დროზე.

💡 მინიშნება (Hint): ReAct-ის მთავარი არსი ისაა, რომ აგენტი ყოველი ნაბიჯის (Action) შემდეგ ჩერდება და აკვირდება შედეგს (Observation), რის მიხედვითაც იღებს შემდეგ გადაწყვეტილებას.
