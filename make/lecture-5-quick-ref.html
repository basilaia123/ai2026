🚨 Panic Button: რა ვქნა, თუ რამე გაფუჭდა? (10-Second Fixes)

  • ❌ შეცდომა "429 Too Many Requests / Rate Limit"? ➔ OpenAI-მ დაგიწესათ წამობრივი ლიმიტი. Make.com-ში ჩაამატეთ "Sleep" მოდული (3-5 წამი) ან შეცვალეთ მოდელი უფრო სწრაფზე (gpt-4o-mini).
  • ❌ Slack-ში Human-in-the-Loop ღილაკი არ რეაგირებს? ➔ შეამოწმეთ Slack Bot Token-ის უფლებები (Scopes: chat:write, commands).
  • ❌ მგრძნობიარე მონაცემი (PII) მაინც გაიპარა LLM-ში? ➔ შეამოწმეთ Regex Masking მოდული - სანამ ტექსტი AI-ს გაეგზავნება, ბარათის ნომრები და პირადი ნომრები აუცილებლად ჩაანაცვლეთ ****-ით.

💰 ROI-ის (Return on Investment) ფორმულა

როგორ ავუხსნათ ბიზნესს ავტომატიზაციის სარგებელი რიცხვებში?

1. დათვალეთ ადამიანის ხარჯი (Current Cost): მაგ: მენეჯერი დღეში ხარჯავს 2 საათს მეილების პასუხზე. თვეში: 40 საათი. ମენეჯერის ხელფასი: $15/სთ. ძველი ხარჯი: 40 * $15 = $600 თვეში. 2. დათვალეთ AI-ის ხარჯი (New Cost): API Tokens + n8n სერვერის ჰოსტინგი. ახალი ხარჯი: მაგ. $20 თვეში. 3. ყოველთვიური მოგება (Monthly Savings): $600 - $20 = $580 დაზოგილი თვეში.

ბიზნესს ეუბნებით: "ეს სისტემა თვეში დაგიზოგავთ 40 საათს და $580-ს, რომლითაც მენეჯერი შეძლებს რეალური გაყიდვების კეთებას."

🛡️ PII Masking Workflow

  1. მიიღე ელფოსტა (Trigger).
  2. გაატარე ლოკალურ Regex/Text Parser-ში, რათა იპოვოს +995 ტელეფონის ნომრები ან @ ნიშნები.
  3. შეცვალე ნაპოვნი მონაცემები `[MASKED]` ტექსტით.
  4. გაგზავნე `[MASKED]` ტექსტი OpenAI-ში გასაანალიზებლად.
  5. მიღებულ პასუხს ისევ მიაბი ორიგინალი იდენტიფიკატორი (ID) და გაგზავნე ბაზაში.

⚖️ Deterministic VS Reasoning (მოკლე წესები)

  • გამოიყენეთ Deterministic (Routers/Filters): გადახდებზე, ბაზაში ჩაწერაზე, მეილის გაგზავნაზე, ნოტიფიკაციებზე. (სადაც შეცდომის ფასი მაღალია).
  • გამოიყენეთ Reasoning (LLMs): ტექსტის გაგებაზე, სურათების ანალიზზე, შინაარსის კატეგორიზაციაზე, შეჯამებაზე.
