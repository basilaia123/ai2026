🚨 Panic Button: რა ვქნა, თუ რამე გაფუჭდა? (10-Second Fixes)

  • ❌ Lindy ან Gumloop აგენტი ვერ ასრულებს ამოცანას? ➔ შეამოწმეთ Run History / Execution Logs. შეამცირეთ ერთ ჯერზე მიცემული დავალებების სია და დაუწერეთ ნაბიჯ-ნაბიჯ (Step-by-step) ფორმატით.
  • ❌ MCP Registry სერვერი არ უკავშირდება აგენტს? ➔ შეამოწმეთ, ხომ არ მოითხოვს სერვერი API გასაღებს (ENV ცვლადს) და სწორად გაქვთ თუ არა მითითებული.
  • ❌ აგენტი ზედმეტ ტოკენებს ხარჯავს და ნელია? ➔ Context Engineering წესი: გამორთეთ ის ხელსაწყოები და მეხსიერების ფაილები, რომლებიც ამ კონკრეტულ ამოცანას არ სჭირდება.

⚖️ პლატფორმის არჩევის სამი წესი

  • Lindy: ბუნებრივ ენაზე მიცემული ინსტრუქცია, ადამიანებთან „საუბრის" ამოცანები.
  • Gumloop: ვიზუალური Canvas, რთული, მრავალსაფეხურიანი მონაცემთა დამუშავება.
  • Make.com AI Modules: უკვე არსებულ Deterministic სცენარში ერთი AI კვანძის ჩამატება.

🔌 MCP Registry-ის სამი ნაბიჯი

  1. მოძებნეთ საჭირო სერვერი mcp.so ან smithery.ai-ზე.
  2. დააკოპირეთ სერვერის კონფიგურაცია (endpoint + credentials).
  3. დააკავშირეთ სერვერი აგენტის ხელსაწყოების სიაში და ჩაატესტეთ ერთ მარტივ მოთხოვნაზე.

🧠 Context Engineering VS Prompt Engineering

  • Prompt Engineering: ერთი კარგად ჩამოწერილი ინსტრუქცია - მარტივი, ერთჯერადი ამოცანებისთვის.
  • Context Engineering: მეხსიერების, ხელსაწყოების, ისტორიისა და ინსტრუქციების სისტემური დაგეგმვა - რთული, მრავალნაბიჯოვანი აგენტებისთვის.

🔐 Agent Trust Checklist

  • Credentials: ვიწრო უფლებები (Least Privilege), არასოდეს ღია ტექსტად.
  • Approvals: კრიტიკულ, შეუქცევად ნაბიჯზე - ადამიანის დასტური სავალდებულო.
  • Audit Trail: ყოველი ხელსაწყოს გამოძახება, კონტექსტი და დასტური ჩაწერილი და ხელმისაწვდომი.
