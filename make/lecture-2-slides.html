🚀 ნაწილი 1: Custom GPTs - სიღრმისეული მიმოხილვა

თქვენი პერსონალიზებული ChatGPT ასისტენტი, რომელიც სპეციფიკურ ამოცანებზეა გამიზნული და ყოველთვის იმახსოვრებს თქვენს ინსტრუქციებს.

📝 Custom GPT ინსტრუქციების ოპტიმიზაცია (Recap)

სტრუქტურა და როლი

როგორც წინა ლექციაზე ვნახეთ, სისტემური ინსტრუქცია უნდა იყოს მკაფიო:

  • Context (ვინ არის?): "შენ ხარ ფინანსური ანალიტიკოსი."
  • Task (რა უნდა გააკეთოს?): "გააანალიზე ატვირთული ფაილი."
  • Tone (როგორ?): "იყავი ლაკონიური და პროფესიონალური."

Out-of-the-box RAG

როდესაც Custom GPT-ში ან Claude Project-ში ფაილს ვტვირთავთ, ის რეალურად ასრულებს RAG-ს (მოძიებით გაუმჯობესებულ გენერაციას).

ეს არის ყველაზე მარტივი გზა, რათა AI-მ ჩვენი კომპანიის ცოდნის ბაზაზე (Knowledge Base) დაყრდნობით ისაუბროს.

კითხვა: მაგრამ რა ხდება კულისებში, როცა 1000-გვერდიან PDF-ს ვტვირთავთ? როგორ პოულობს ის ზუსტ პასუხს?

🎨 Claude-ის პროექტები - მიმოხილვა

რა არის Claude-ის პროექტი?

Claude-ის პერსონალიზებული სამუშაო სივრცე, სადაც თავსდება დოკუმენტები, კონტექსტი და ინსტრუქციები ერთ ადგილას.

✅ Claude-ის უპირატესობები

  • 200K ტოკენი კონტექსტი - ძალიან დიდი ფაილებისთვის.
  • უკეთესი ანალიტიკური უნარები.
  • ქართული ენის შესანიშნავი მხარდაჭერა.
  • უფრო სტრუქტურირებული პასუხები.

⚠️ GPT vs Claude

  • GPT: მეტი plugin-ი, უფრო შემოქმედებითი.
  • Claude: უკეთესი ანალიზი, უფრო დეტალური.

აირჩიეთ პროექტის მიხედვით!

იდეალურია:

  • დოკუმენტების ანალიზი (ანგარიშები, კვლევითი ნაშრომები).
  • კოდის განხილვა და რეფაქტორინგი.
  • სტრატეგიული დაგეგმვა.
  • სასწავლო მასალების შედგენა.

1ინდექსირება (Indexing)

რა ხდება:

  • დოკუმენტები იყოფა მცირე ფრაგმენტებად (chunks).
  • თითოეული ფრაგმენტი გარდაიქმნება „ემბედინგებად“ (ციფრული წარმოდგენა).
  • ინახება ვექტორულ მონაცემთა ბაზაში.

ეს ყველაფერი ხდება ავტომატურად, როცა დოკუმენტს ტვირთავთ!

2მოძიება (Retrieval)

მომხმარებლის კითხვაზე:

  • კითხვა გარდაიქმნება ემბედინგად.
  • ეძებს ყველაზე მსგავს ფრაგმენტებს მონაცემთა ბაზაში.
  • მოიძიებს Top-K ყველაზე რელევანტურ ფრაგმენტებს (მაგ: Top-5).

3გენერაცია (Generation)

AI აყალიბებს პასუხს:

  • იღებს მოძიებულ ფრაგმენტებს.
  • იღებს მომხმარებლის კითხვას.
  • აყალიბებს პასუხს, რომელიც ეყრდნობა ფრაგმენტებს.

🔄 ReAct Framework

Reasoning + Acting = ReAct

ReAct არის პოპულარული framework, რომელიც აერთიანებს მსჯელობას (Reasoning) და მოქმედებას (Acting).

ReAct ციკლის 3 ნაბიჯი

1️⃣ Thought

(Reasoning)

„რა უნდა გავაკეთო?"

→
2️⃣ Action

(Acting)

„გავაკეთე ეს"

→
3️⃣ Observation

(Result)

„ვნახე შედეგი"

↻ ციკლი მეორდება, სანამ ამოცანა არ გადაწყდება

💡 ცხოვრებისეული ანალოგია: "დეტექტივი შერლოკ ჰოლმსი"

Thought (მსჯელობა): "იატაკზე ტალახიანი ნაკვალევია. სავარაუდოდ, ეჭვმიტანილი წვიმიან ბაღში გავიდა."
Action (მოქმედება): იღებს ლუპას და ზომავს ნაკვალევს (ხელსაწყოს / Tool-ის გამოძახება).
Observation (დაკვირვება): "ნაკვალევი 43 ზომის სამხედრო ჩექმისაა."
Next Thought (ახალი მსჯელობა): "ახლა უნდა შევამოწმო სამხედრო ბაზის სია..." ➔ აგენტიც ზუსტად ასე, ნაბიჯ-ნაბიჯ იკვლევს და მოქმედებს, სანამ მიზანს არ მიაღწევს!

💡 რატომ არის ReAct ეფექტური?

  • Transparency: ნათლად ჩანს, რას „ფიქრობს" Agent
  • Debuggability: ადვილია შეცდომების იდენტიფიცირება
  • Controllability: შეგიძლია ჩაერიო პროცესში
  • Self-Correction: Agent-ს შეუძლია საკუთარი შეცდომების გამოსწორება

💻 Practical Implementation - კოდის მაგალითი

მარტივი Agent-ის შექმნა LangChain-ით

🐍 Python Code Example

from langchain.agents import initialize_agent, AgentType
from langchain.chat_models import ChatOpenAI
from langchain.tools import Tool

# 1. დააყენე LLM
llm = ChatOpenAI(temperature=0, model="gpt-4")

# 2. განსაზღვრე Tools
def search_web(query):
    """ძებნის სიმულაცია"""
    return f"Results for: {query}"

tools = [
    Tool(
        name="Search",
        func=search_web,
        description="გამოიყენე ინფორმაციის მოსაძებნად"
    )
]

# 3. შექმენი Agent
agent = initialize_agent(
    tools=tools,
    llm=llm,
    agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION,
    verbose=True
)

# 4. გაუშვი Agent
result = agent.run("რა ამინდია დღეს თბილისში?")
print(result)

2. Data Leakage

Agent-მა შეიძლება გაავრცელოს კონფიდენციალური ინფორმაცია

  • Personal data
  • Business secrets

Agent-მა შეიძლება შეასრულოს დაუშვებელი ქმედებები

  • Delete data
  • Financial transactions
  • System changes

ყველა ქმედების ფიქსირება

🔌 Model Context Protocol (MCP) - ახალი სტანდარტი

რა არის MCP?

MCP (Model Context Protocol) არის უნივერსალური, ღია სტანდარტი, რომელიც საშუალებას აძლევს AI აგენტებს (მაგ. Claude) უსაფრთხოდ დაუკავშირდნენ ლოკალურ მონაცემებსა და სერვისებს.

როგორ მუშაობს ადრე (API)?

  • რთული ინტეგრაცია (OAuth, API Keys).
  • მონაცემების სერვერზე ატვირთვის აუცილებლობა.

როგორ მუშაობს MCP (2026)?

  • პირდაპირი კავშირი: აგენტი კითხულობს თქვენს ლოკალურ ფაილებს, GitHub რეპოზიტორებს ან მონაცემთა ბაზებს.
  • უსაფრთხოება: მონაცემები არ ტოვებს თქვენს მოწყობილობას თქვენი ნებართვის გარეშე.

💡 ცხოვრებისეული ანალოგია: "AI-ს უნივერსალური USB-C პორტი"

წარსულში (ქაოსი): ყოველ ტელეფონს, კამერასა და გაჯეტს თავისი უნიკალური დამტენი კაბელი სჭირდებოდა. ერთი სადენი მეორეს არ ერგებოდა.
დღეს (MCP): როგორც USB-C გახდა მსოფლიო სტანდარტი და ერთი კაბელით ერთდება ყველაფერი, ისე გახდა MCP უნივერსალური პორტი AI-სთვის - ერთი და იგივე სტანდარტით Claude/AI უკავშირდება თქვენს ლოკალურ ფაილებს, PostgreSQL ბაზას, GitHub-ს, Notion-სა და ბრაუზერს!
