📋 სწრაფი ცნობარი (Cheat Sheet): ლექცია 3

🚨 Panic Button: რა ვქნა, თუ რამე გაფუჭდა? (10-Second Fixes)

  • ❌ წითელი შეტყობინება "401 / Unauthorized"? ➔ დაგავიწყდათ API გასაღების ჩასმა. შედით პარამეტრებში (Connection) და ჩასვით გასაღები თავიდან.
  • ❌ "JSON syntax error"? ➔ ბოლოში დარჩა ზედმეტი მძიმე ან აკლია ბრჭყალი ("). გამოიყენეთ JSONLint.com.
  • ❌ ავტომატიზაცია არ რეაგირებს? ➔ შეამოწმეთ სცენარის ჩამრთველი მარცხენა ქვედა კუთხეში: ხომ არ წერია "OFF"? გადართეთ "ON"-ზე.
  • ❌ Webhook-ზე მონაცემი არ მოდის? ➔ დააჭირეთ "Re-determine data structure" Webhook-ის მოდულში და გააგზავნეთ 1 სატესტო მოთხოვნა.

Make.com-ის მთავარი მოდულები

  • Iterators (მწვანე მოდული): Array ➔ ცალკეულ ობიექტებად დაშლა.
  • Aggregators (მწვანე მოდული): ობიექტები ➔ ერთიან Array-დ შეკვრა.
  • Routers (მწვანე მოდული): მონაცემთა გზაჯვარედინი. ერთი Flow იყოფა რამდენიმედ.
  • Text Parser (ლურჯი მოდული): ტექსტის დაყოფა, ან Regular Expressions (Regex) გამოყენება.
  • HTTP Module (იისფერი მოდული): ნებისმიერი გარე API-ის გამოძახება, რასაც ოფიციალური ინტეგრაცია არ აქვს.

📝 JSON-ის კითხვა: ობიექტი VS მასივი

{ "user": { <-- ეს არის Object (ფიგურული ფრჩხილები) "name": "David", "role": "Admin" }, "orders": [ <-- ეს არის Array (კვადრატული ფრჩხილები) { "id": 1, "total": 100 }, { "id": 2, "total": 250 } ] }

გახსოვდეთ: თუ ხედავთ [ ], ესეიგი სიაა, და დაგჭირდებათ Iterator!

🔌 API მოთხოვნის აწყობის Checklist (HTTP Module)

  1. URL: სად ვაგზავნით? (მაგ. https://api.openweathermap.org/data/2.5/weather)
  2. Method: GET (კითხვა), POST (შექმნა), თუ PUT (განახლება)?
  3. Headers: გვაქვს თუ არა ჩასმული Authorization: Bearer [API_KEY]?
  4. Query String (Parameters): მივუთითეთ თუ არა დამატებითი ფილტრები? (მაგ. ?q=Tbilisi&units=metric)
  5. Parse response: ჩართული გვაქვს თუ არა Yes, რათა Make.com-მა JSON წაიკითხოს?
