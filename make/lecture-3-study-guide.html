📖 სასწავლო გზამკვლევი: ლექცია 3 (API და Make.com)

1. მონაცემთა სტრუქტურები (Arrays & Objects)

იმისათვის რომ ავტომატიზაცია ავაწყოთ, უნდა გვესმოდეს როგორ ინახავს სერვერი მონაცემებს:

  • Object (ობიექტი): ერთი კონკრეტული ნივთის ან ადამიანის აღწერა. მას აქვს თვისებები (Keys) და მნიშვნელობები (Values).
  • Array (მასივი): ობიექტების სია. (მაგ. კალათაში არსებული 5 პროდუქტი).

რატომ არის ეს მნიშვნელოვანი? Make.com-ში თუ ამოიღებთ "Array"-ს, მას სჭირდება Iterator მოდული, რათა სია დაიშალოს და თითოეულ ობიექტს ცალკე მიხედოთ (მაგ. გაუგზავნოთ 5 ცალკეული მეილი).

2. API - რესტორნის ანალოგია

API-ის გასაგებად, წარმოიდგინეთ რესტორანი:

  • მომხმარებელი (თქვენ): გაქვთ მენიუ და ითხოვთ საჭმელს.
  • ოფიციანტი (API): იღებს თქვენს შეკვეთას და მიაქვს სამზარეულოში. ოფიციანტის გარეშე, სამზარეულოში ვერ შეხვალთ (უსაფრთხოება).
  • სამზარეულო (სერვერი/მონაცემთა ბაზა): ამზადებს მოთხოვნილ ინფორმაციას და ატანს ოფიციანტს.
  • შეკვეთა მოვიდა: ოფიციანტს მოაქვს საჭმელი (ეს არის API Response JSON ფორმატში).

3. HTTP სტატუს კოდები - რას ნიშნავს რიცხვები?

როცა API-ს უკავშირდებით, ის გაძლევთ სტატუსს (3-ნიშნა რიცხვს). ამ რიცხვების გაგება Debugging-ისთვის კრიტიკულია:

  • 2xx (წარმატება): 200 OK - ყველაფერი იდეალურადაა.
  • 4xx (კლიენტის შეცდომა): შეცდომა თქვენს მხარესაა.
    • 400 Bad Request - არასწორი პარამეტრები გაგზავნეთ.
    • 401 Unauthorized - API Key არასწორია ან დაგავიწყდათ Headers-ში ჩასმა.
    • 404 Not Found - მონაცემი (ან URL) არ არსებობს.
  • 5xx (სერვერის შეცდომა): შეცდომა სისტემის მხარესაა. 500 Internal Server Error - უნდა დაელოდოთ სერვერის გამოსწორებას.
