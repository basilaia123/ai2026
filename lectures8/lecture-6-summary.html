ლექცია 6 - შეჯამება

🤖 სამუშაო პროცესების ავტომატიზაცია და AI Agents

Make.com 2026 "Run an Agent", Model Context Protocol (MCP), n8n & აგენტური პატერნები

🎯 1. 2026 წლის პარადიგმის ცვლა: Deterministic-დან Agentic-მდე

წარსული (Deterministic / If-This-Then-That): ხისტი, წინასწარ გაწერილი წესები (მაგ. Zapier-ის კლასიკური ნაბიჯები). მონაცემთა ფორმატის ოდნავი ცვლილებისას ან არასტრუქტურირებული ტექსტისას სისტემა ფუჭდებოდა.

2026 წლის რეალობა (Goal-Oriented AI Agents): სისტემას ეძლევა საბოლოო მიზანი (Goal) და ხელსაწყოების ნაკრები. AI თავად იღებს გადაწყვეტილებას (Reasoning), რომელი ხელსაწყო როდის გამოიყენოს და როგორ შეასწოროს შეცდომა.

მახასიათებელი ტრადიციული ავტომატიზაცია 2026 Agentic Workflow
ლოგიკა ხისტი წესები: IF X THEN Y მიზანზე ორიენტირებული: Achieve Goal Z using Tools
არასტრუქტურირებული მონაცემები ხშირი შეცდომები ტექსტის, ხმისა და დოკუმენტების ბუნებრივი დამუშავება
შეცდომებთან გამკლავება სცენარის შეჩერება (Error Crash) თვითშესწორება (Self-Correction & Fallback)

🛠️ 2. Make.com 2026 "Run an Agent" ჰექსაგონალური მოდული

Make.com-ის 2026 წლის უმთავრესი ევოლუცია არის "Run an Agent" მოდული, რომელმაც გააერთიანა 4 ცალკეული ფუნქცია:

🧠 1. Brain (მოდელის არჩევა)

  • Frontier LLM-ების მხარდაჭერა: GPT-4o, Claude 3.5 Sonnet, Gemini 2.0 Flash;
  • System Instructions და ქცევის წესების მკაცრი კონტროლი;
  • Reasoning ბიუჯეტისა და ტემპერატურის რეგულირება.

📚 2. Knowledge (In-Module RAG)

  • PDF, DOCX და FAQ დოკუმენტების ატვირთვა პირდაპირ მოდულში;
  • გარე ვექტორული ბაზების გარეშე მომენტალური ძიება;
  • მკაცრად Grounded პასუხები კომპანიის მასალებზე დაყრდნობით.

🛠️ 3. Tools (ხელსაწყოების ნაკრები)

  • აგენტს შეუძლია ავტონომიურად გამოიძახოს სხვა Make სცენარები;
  • გარე REST API-ების და Webhook-ების ინტეგრაცია;
  • Model Context Protocol (MCP) ხელსაწყოების გამოძახება.

💾 4. Memory (მეხსიერების კონტექსტი)

  • Short-term Memory სესიის ფარგლებში;
  • Long-term Persistent Memory მომხმარებლის პროფილის დასამახსოვრებლად;
  • უწყვეტი დიალოგური კონტექსტი.

🔍 Glass-Box Reasoning View & Chat Sandbox:

Glass-Box View: აქრობს „Black Box“-ის პრობლემას - გაშვების დროს შეგიძლიათ რეალურ დროში ნახოთ აგენტის აზროვნების ჯაჭვი (Chain of Thought): რა მიზანი დაისახა, რომელი ხელსაწყო გამოიძახა და რა შედეგი მიიღო.
Chat Sandbox: სამუშაო ტილოზე (Canvas) ჩაშენებული ინტერაქტიული ჩათი, სადაც შეგიძლიათ გატესტოთ აგენტის ლოგიკა რეალურ მონაცემებზე გაშვებამდე.

🔌 3. Model Context Protocol (MCP) სტანდარტიზაცია

MCP (Model Context Protocol) არის Anthropic-ის მიერ შექმნილი და ინდუსტრიის მიერ აღიარებული ღია სტანდარტი, რომელმაც ჩაანაცვლა API glue-კოდი.

[AI Host: Make / Cursor / Claude Desktop] │ (MCP Client) ▼ (სტანდარტული JSON-RPC პროტოკოლი) [MCP Servers: PostgreSQL, GitHub, Notion, CRM, Local Filesystem]
  • ერთხელ გაწერილი ხელსაწყო: ერთი MCP სერვერი თანაბრად მუშაობს Make-ში, Cursor-ში, Claude Desktop-სა და n8n-ში;
  • უსაფრთხოება: მკაცრად განსაზღვრული უფლებები (Read-only ან Write ნებართვები).

🛡️ 4. n8n AI Agents & ლოკალური პრივატულობა (GDPR)

საქართველოს საბანკო, სამედიცინო და იურიდიული სექტორისთვის, სადაც პერსონალური მონაცემების (PII) ღრუბელში გატანა აკრძალულია, წამყვანი გადაწყვეტაა n8n Self-Hosted.

  • On-Premise გაშვება: Docker-ით კომპანიის საკუთარ ლოკალურ სერვერზე;
  • ლოკალური LLM ინტეგრაცია: Ollama-ს მეშვეობით (Llama 3.3, DeepSeek-R1);
  • ულიმიტო ოპერაციები: არ გააჩნია ყოველთვიური ოპერაციების გადასახადი;
  • ნატიური MCP კლიენტი და სერვერი: სრული თავსებადობა თანამედროვე ხელსაწყოებთან.

🏗️ 5. Anthropic-ის აგენტური პატერნები

🔀 Routing (მარშრუტიზაცია)

AI აფასებს შემოსულ შეკითხვას და გადაამისამართებს შესაბამის სპეციალიზებულ განშტოებაზე (მაგ. ბილინგი, ტექნიკური მხარდაჭერა, გაყიდვები).

⚡ Parallelization (პარალელიზაცია)

დავალება იყოფა რამდენიმე ქვედავალებად და მუშავდება ერთდროულად სხვადასხვა მოდელით (მაგ. სენტიმენტის ანალიზი + თარგმანი + ტეგირება).

🐝 Orchestrator-Workers

მთავარი ორკესტრატორი აგენტი აანალიზებს კომპლექსურ მიზანს, ურიგებს დავალებებს ვიწრო აგენტებს და აჯამებს საბოლოო პასუხს.

🔁 Evaluator-Optimizer

ერთი აგენტი აგენერირებს შედეგს, მეორე კი ამოწმებს ხარისხს. თუ მოთხოვნა არ შესრულდა, უბრუნებს უკან კორექტირებისთვის.

👤 Human-in-the-Loop (HITL) - ადამიანის თანხმობის ეტაპი:

მაღალი რისკის ოპერაციები (ფინანსური გადარიცხვა > $1000, ოფიციალური კონტრაქტის გაგზავნა, მომხმარებლის ბაზის წაშლა) ავტომატურად ჩერდება და ითხოვს ადამიანის დადასტურებას Slack-ში ან Email-ში ღილაკზე დაჭერით.
